## 🔎 Overview

This project turns long English conversations into short, readable summaries. It covers the full machine-learning lifecycle:

1. **Train** – fine-tune [`t5-small`](https://huggingface.co/t5-small) (60M parameters) on the [SAMSum](https://huggingface.co/datasets/knkarthick/samsum) dataset (16K+ dialogues) using Hugging Face Transformers through a modular, config-driven pipeline.
2. **Use** – summarize text from a polished **Streamlit** web app that loads the trained model directly (no separate API server needed).

The code follows a clean component / pipeline / configuration-manager layout, so every stage can be changed from YAML files without touching the core logic.

> 💡 **Key detail:** T5 is a multi-task model trained with text prefixes. Every input must be prepended with the **`summarize: `** task prefix — at training *and* inference time. Without it, the model falls back to copying the input instead of summarizing.

## ✨ Features

**Model and app**

- Fine-tuned T5-small abstractive summarizer (ROUGE-L ≈ 0.39 on the SAMSum test set — see [Results](#-results))
- Model is loaded once and cached with `@st.cache_resource`, not per request
- Config-driven training pipeline (`config.yaml` and `params.yaml`)
- Single-command deployment on [Streamlit Community Cloud](https://share.streamlit.io/)

**Web interface**

- **Long-text support**: texts of any length are split into sentence-aligned chunks, summarized, and merged
- **Summary detail**: *Standard* or *Concise* (merges the part summaries into one short summary)
- **Output format**: paragraph or bullet points
- **File upload**: TXT, MD, PDF and DOCX
- **Key-term highlighting** inside the summary, plus key-term chips
- **Quality stats**: reduction %, reading time saved, Flesch readability (before → after), processing time
- **Listen** to the summary (browser text-to-speech), **copy** it, or **download** it as `.txt` / `.md`
- **Dark and light mode** with an animated circular-reveal transition (state is kept in the URL, e.g. `?theme=light`)
- Session **history** and a warning when the text is not English
- Keyboard shortcut: `Ctrl + Enter` to summarize

## 🏗 Architecture

```mermaid
flowchart LR
    U([User]) --> S[Streamlit UI<br/>streamlit_app.py]
    S --> P[PredictionPipeline]
    P --> M[(Fine-tuned<br/>T5-small model)]
    M --> P --> S --> U
```

The Streamlit app loads the trained model in-process. For texts longer than the model's input window, the app splits the text into chunks of about 350 words, runs inference once per chunk, and combines the results.

## 🚀 Getting Started

### Prerequisites

- Python **3.11**
- [Conda](https://docs.conda.io/) (recommended) or `venv`
- A trained model available to `PredictionPipeline` (see [Training Pipeline](#-training-pipeline))

### 1. Clone the repository

```bash
git clone https://github.com/engSalah-dot/Text-Summarization.git
cd Text-Summarization
```

### 2. Create an environment

```bash
conda create -n summary python=3.11 -y
conda activate summary
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Run the app

```bash
streamlit run streamlit_app.py
```

Open the URL printed in the terminal (usually `http://localhost:8501`).

> The first request is slow because the model is being loaded into memory; after that, inference is fast (GPU) or moderate (CPU).

## 💡 Usage

1. Paste text, click **Try a sample**, or upload a file.
2. Choose **Standard** or **Concise**.
3. Click **Summarize** (or press `Ctrl + Enter`).
4. Switch between paragraph and bullets, highlight key terms, listen, copy, or download the result.

You can also use the prediction pipeline directly from Python:

```python
from src.text_summarizer.pipeline.prediction import PredictionPipeline

pipe = PredictionPipeline()
summary = pipe.predict("summarize: Hannah: Hey, do you have Betty's number? Amanda: Lemme check...")
print(summary)
```

## 📊 Results

Fine-tuned T5-small evaluated with ROUGE on the SAMSum **test set** (819 samples):

| Metric | Validation | Test |
|---|---|---|
| ROUGE-1 | 0.499 | **0.474** |
| ROUGE-2 | 0.257 | **0.231** |
| **ROUGE-L** | **0.415** | **0.392** |
| ROUGE-Lsum | 0.414 | **0.392** |

**For context:** large models such as BART-large and T5-large reach ROUGE-L ≈ 0.41–0.43 on SAMSum — this 60M-parameter model comes within ~2 points of models several times its size.

Training log highlights:

- Convergence was monitored every 500 steps; ROUGE-L plateaued after ~3,500 steps, so longer training is unlikely to help much.
- Final evaluation loss: **1.63**.

Example output:

| | |
|---|---|
| **Dialogue** | *Hannah asks Amanda for Betty's number; Amanda can't find it and suggests asking Larry, who called Betty last time they were at the park together...* |
| **Reference summary** | *Hannah needs Betty's number but Amanda doesn't have it. She needs to contact Larry.* |
| **Model summary** | *Betty's number is not available. Amanda can't find it. Larry called Betty last time they were at the park together.* |

## 🧪 Training Pipeline

The pipeline is modular and every stage reads its settings from YAML:

```mermaid
flowchart LR
    A[Data Ingestion] --> B[Data Validation] --> C[Data Transformation] --> D[Model Trainer] --> E[Model Evaluation]
```

Run the full pipeline:

```bash
python main.py
```

**Base model:** [`t5-small`](https://huggingface.co/t5-small) — 60.5M parameters

**Dataset:** [`knkarthick/samsum`](https://huggingface.co/datasets/knkarthick/samsum)

| Split | Samples |
|---|---|
| Train | 14,731 |
| Validation | 818 |
| Test | 819 |

**Training setup** (Google Colab, Tesla T4):

| Parameter | Value |
|---|---|
| `num_train_epochs` | 5 |
| `learning_rate` | 2e-4 |
| Effective batch size | 16 |
| Precision | FP16 |
| Training time | ~56 minutes |

### Preprocessing

Every dialogue is tokenized as `"summarize: " + dialogue` (max length 512), and summaries as labels (max length 128). The same prefix is applied at inference time.

### Development workflow

When adding or changing a pipeline stage, follow this order:

1. Update `config/config.yaml`
2. Update `params.yaml`
3. Update the entity (`src/text_summarizer/entity`)
4. Update the configuration manager (`src/text_summarizer/config`)
5. Update the components (`src/text_summarizer/components`)
6. Update the pipeline (`src/text_summarizer/pipeline`)
7. Update `main.py`
8. Update `streamlit_app.py`

## 🩹 Troubleshooting

| Problem | Fix |
|---|---|
| Very slow first request | The model is loading into memory or running on CPU; later requests are faster |
| Poor summary for non-English text | The model is trained for English only |
| Model copies the input instead of summarizing | The `summarize: ` task prefix is missing from the input — T5 requires it at inference time |
| App crashes on startup | Make sure the trained model files exist at the path configured in `config.yaml` |

---

## ⚠️ Limitations

- **English only**: the model is trained and evaluated on English text.
- **Abstractive model**: summaries can occasionally contain inaccuracies, so check important facts against the source.
- **Speed**: inference on CPU is slower than on GPU, especially for long documents.
